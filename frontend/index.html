SYSTEM DESIGN

Local-first, event-driven research orchestration

The working V2 prototype uses a FastAPI service to create research runs, LangGraph to coordinate steps, OpenAlex to retrieve research metadata, a locally served LLM for reasoning, and SQLite to persist runs and events. The V3 frontend visualizes events through server-sent events (SSE).

Research topic→PI→Researcher→Analyst→Critic↺RefineSearch / Review→Writer
Orchestration · LangGraphAgent state, conditional transitions, and bounded critique loops.
Inference · llama.cppLocal OpenAI-compatible API with Holo-3.1-35B-A3B for the existing prototype.
Research retrieval · OpenAlexTopic-driven paper search and critique-triggered additional retrieval.
Backend · FastAPI + SQLiteRun creation, persisted events, report storage, and SSE streaming.
Frontend · ViteVisualizes agent events and progress in a debate-room metaphor.
Observability · PlannedMLflow integration for comparing runs, latency, model configurations, and quality metrics.

What makes the system interesting?

Critique is not merely an output label: in V2 it can trigger additional evidence retrieval before the workflow returns to analysis. The maximum loop count prevents unbounded execution.

Architecture describes the developed V2 prototype; Live Research connects to its API through the same-origin /api proxy.

Illustrative ADAS research hypothesis

Complete replacement of modular ADAS by end-to-end AI by 2030 is uncertain. A hybrid architecture — learned driving intelligence paired with independent safety supervision and deterministic control — may be more plausible. This is a provisional synthesis, not a validated prediction.

Manager-facing takeaway: This project demonstrates practical work across local LLM serving, graph-based agent orchestration, external research retrieval, backend APIs, persistent execution state, and an interactive frontend. The next phase is to quantify whether critique improves evidence quality and report reliability.
